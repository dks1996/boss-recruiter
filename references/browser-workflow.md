# BOSS直聘浏览器自动化操作 SOP

本文件定义在 BOSS直聘上执行候选人搜索与沟通的标准操作流程和风控规范。Step 2 与 Step 4 执行前必须完整阅读本文件。

## ⚡ 实战提速要点（2026-11-17 复盘，先看这里）

1. **浏览器一律用官方内置浏览器**（`mcp__browser__*` / workbuddy-browser-use）：第三方 Playwright/Chrome 引擎会因 `navigator.webdriver=true` 被 BOSS 识别，页面几秒内被强制跳到 about:blank/百度，稳定复现；改 webdriver 特征属破解反爬红线，禁止。开启浏览器控制后当前会话不热加载工具，若无 `mcp__browser__*` 工具直接让用户新建会话。
2. **渠道选择决定成本**：「推荐牛人」页卡片上的「打招呼」**免费**；「搜索」页「联系Ta」是 **¥388 畅聊卡付费墙**（热搜牛人消耗 2-3 次权益）。主动联系一律走推荐牛人页；搜索页只用于采集/评分。评分出的高匹配 A 级候选人通常也会出现在推荐牛人页，可免费联系。
3. **打招呼交互**：点「打招呼」→发系统默认语、按钮变「继续沟通」→进聊天 → contenteditable 输入框打字 → **按 Enter 发送**（比坐标点发送按钮可靠）。沟通计数 +1 可验证是否真实发出。
4. **DOM 节点操作优先**：内置浏览器视口宽度在截图间跳变，坐标 `cua_click` 不可靠，一律用 `dom_cua_*` 按 node_id 操作，且每次操作前重新 `get_visible_dom`（节点会 stale）。DOM 每次只返回视口附近候选人，用 `cua_execute` 批量 PageDown 逐屏采集。
5. 更完整的坑点、标准快速路径与决策点清单见仓库根目录 `LESSONS.md`。

## 一、能力检测与启用

1. 执行任何网页操作前，确认浏览器控制能力可用。优先使用 `workbuddy-browser-use` skill；若不可用，检查是否已安装 Browser Use 插件。
2. 能力不可用时的处理顺序：
   - 提示用户在设置中开启「浏览器控制」；
   - 或通过插件市场搜索并安装 Browser Use 插件；
   - 在能力恢复前，不得声称已完成搜索或沟通，不得编造候选人数据。
3. 浏览器控制只用于 BOSS直聘相关页面，不做无关浏览。

## 二、登录流程

1. 打开 BOSS直聘企业招聘端（https://www.zhipin.com）。
2. 检查登录状态。若未登录，选择「扫码登录」并把二维码展示给用户，请其用 BOSS直聘 App 扫码确认。
3. 不要索取、记录或存储用户的账号密码、短信验证码。
4. 登录成功后确认进入企业后台（而非个人求职端）。若发现是求职端，切换到企业端再继续。

## 三、候选人搜索流程

1. 进入「人才搜索」或「推荐牛人」页面。
2. 按「岗位匹配标准卡」逐项设置筛选条件：岗位关键词、城市、工作经验、学历、年龄、期望薪资、活跃状态。
3. 执行搜索，记录本次搜索条件与结果数量。
4. 从结果列表逐条采集候选人卡片字段：候选人标识（姓名或匿名昵称）、当前职位、当前公司、工作年限、学历、技能标签、期望薪资、最近活跃时间、求职意向。
5. 对总分潜力较高的候选人，点击进入在线简历详情页，补充采集：工作经历要点、项目经验、教育背景、期望岗位、到岗时间。
6. 采集过程中遵守频率限制，不要快速连续翻页或高频点击。
7. 将采集结果写入结构化候选人列表，字段与 `scripts/build_shortlist.py` 的 `CANDIDATE_SCHEMA` 保持一致。

## 四、沟通与索要简历流程

1. 只为 A、B 级候选人发送打招呼消息。
2. 发送前按 `references/message-templates.md` 生成个性化消息，逐条检查：是否引用了候选人真实经历、是否符合公司事实、是否包含清晰的公司卖点。
3. 通过浏览器控制发送消息，记录发送时间与候选人标识。
4. 每次操作后等待页面加载完成再读取结果，不要抢在渲染前操作。
5. 对已回复的候选人：
   - 先用追问语核实关键门槛；
   - 再索要完整简历或确认使用在线简历；
   - 更新沟通状态（已打招呼 / 已回复 / 已收简历 / 待跟进 / 拒绝 / 无响应）。
6. 收到简历后按 `references/screening-framework.md` 评估，回填评分与结论。
7. 沟通内容必须真实，不得代替用户做超出授权的承诺。

## 五、风控红线（必须遵守）

- 主动打招呼每小时不超过 20 人、每天不超过 100 人；两次操作之间加入 3-8 秒随机间隔，模拟真人节奏。
- 禁止给同一候选人短时间重复发送相同消息；禁止批量群发完全雷同的模板。
- 禁止绕过验证码、破解反爬、使用外挂或第三方群发工具。
- 禁止使用虚假身份、虚构公司信息或夸大承诺。
- 遇到以下任一情况，**立即停止全部自动化操作**并通知用户：
  - 页面出现验证码、安全验证、异常登录提示；
  - 平台弹出风控警告或限制操作提示；
  - 账号被要求重新登录或出现异常；
  - 候选人明确表示拒绝或投诉。
- 候选人隐私数据仅用于本次招聘，不对外传播，不在回复中展示无关个人信息。

## 六、异常处理

| 异常 | 处理方式 |
|------|----------|
| 页面加载失败 | 等待后重试一次；仍失败则记录并跳过该候选人 |
| 候选人信息缺失 | 标注「信息不足」，不强行编造，按低置信度处理 |
| 收到简历但无法解析 | 把原始内容记录到备注，提示用户人工查看 |
| 浏览器控制中断 | 保存已采集数据，通知用户从断点继续 |
| 用户要求停止 | 立即停止，保存已采集数据并输出阶段性结果 |
| 页面几秒跳到 about:blank/百度 | 第三方引擎被反爬识别，切换官方内置浏览器 |

## 七、数据记录规范

- 每位候选人必须保留唯一标识，便于跨环节追踪。
- 每次沟通都要记录时间、内容与状态变化。
- 采集与评估过程中不臆造字段；信息不足时明确标注「信息不足」。
